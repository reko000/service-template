# QAレビュアーワークフロー（QA Reviewer）

開発者が作成したPRを受け取り、コードレビュー・E2Eテスト・実際のブラウザ操作による検証を行い、品質を判定する。

## 使用スキル

| スキル | 用途 |
|---|---|
| `code-review` | コードレビュー・アーキテクチャ監査 |
| `test-runner` | E2Eテスト再実行 |
| `github-ops` | PRコメント・レビュー判定 |

## 手順

### 1. コードレビュー

`code-review` スキルに従い、PRのdiffを確認する。

確認観点:
- `CLAUDE.md` の「鉄の掟」への準拠
- 横方向インポートの有無
- Smart/Dumb分離の妥当性
- セキュリティ上の問題（ハードコードされた秘密情報、SQLインジェクション等）
- 明らかなバグやロジックエラー

### 2. E2Eテスト実行

`test-runner` スキルに従い、テストを再実行する。

```bash
# apps/web ディレクトリで実行
npx playwright test
npx vitest run
```

- 全テストがパスすること
- 新規テストが元のIssueのシナリオを網羅していること

### 3. ブラウザで実際に操作して確認

**QAの最も重要な責務。** 開発サーバーを起動し、実際にブラウザで操作する。

```bash
npm run dev
```

確認観点:
- ユーザーとして自然に操作できるか（UX）
- 画面遷移・レイアウトに違和感がないか
- レスポンシブ対応（必要な場合）
- エラー時のフィードバック表示
- a11y（キーボード操作、スクリーンリーダー対応）

### 4. 判定

レビュー結果を `github-ops` スキルに従いPRにコメントする。

| 判定 | 条件 | アクション |
|---|---|---|
| **Approve** | 全チェックOK | PRにApproveレビューを付与 |
| **Request Changes（コード修正）** | テスト失敗、バグ、規約違反 | 具体的な修正箇所をPRコメントに記載 |
| **Request Changes（要件の問題）** | テストシナリオ自体が不適切、要件漏れ | Issueにコメントし、プランナーへの差し戻しをオーケストレーターに報告 |

### レビューコメントのフォーマット

```markdown
## QA Review Result: [Approve / Request Changes]

### コードレビュー
- [ ] CLAUDE.md 準拠
- [ ] 横方向インポートなし
- [ ] セキュリティ問題なし

### テスト実行
- [ ] E2E: 全パス
- [ ] Unit: 全パス

### ブラウザ操作確認
- [ ] 主要シナリオの動作確認
- [ ] エッジケースの動作確認
- [ ] UX/UIに違和感なし

### 指摘事項
（あれば記載）
```
