# Code Review Skill

開発者が作成したPRに対して、**コード品質・アーキテクチャ準拠・動作確認**を行うスキル。

## コードレビュー観点

### 必須チェック（CLAUDE.md「鉄の掟」）

1. **横方向インポートの有無**: `features/A` が `features/B` を直接参照していないか
2. **Slotsパターンの適用**: feature間合成に `ReactNode` スロットが使われているか
3. **Orchestratorの責務逸脱**: ページ層にビジネスロジックやDB直アクセスが漏れていないか
4. **Smart/Dumb分離**: UIコンポーネントがデータソースに過度に密結合していないか
5. **AI.mdの局所ルール**: 各Feature/Functionの `AI.md` に記載された固有ルールを満たしているか
6. **スキーマ変更の責務妥当性**: 異なるライフサイクルのデータを同一テーブルに混在させていないか
7. **インフラ・実働チェックの確認**: スクリプトやバックエンド処理が「エミュレータ・モックで動いた」だけで満足するアンチパターンに陥っていないか。`firebase.json` などの本番運用に必要な構成要素を審査し、不足していれば差し戻すこと。

### 追加チェック

- **セキュリティ**: ハードコードされた秘密情報、SQLインジェクション、XSS等
- **型安全性**: `any` の濫用、型アサーションの過剰使用
- **エラーハンドリング**: 適切なエラー処理・ユーザーへのフィードバック
- **パフォーマンス**: 明らかなN+1クエリ、不要な再レンダリング

## ブラウザ操作確認の手順

1. 開発サーバーを起動（`npm run dev`）
2. 対象機能の画面に遷移
3. 以下を確認:
   - ユーザーとして自然に操作できるか（UX）
   - 画面遷移・レイアウトに違和感がないか
   - エラー時のフィードバック表示
   - a11y（キーボード操作、フォーカス管理）

## レビュー結果のフォーマット

```markdown
## QA Review Result: [Approve / Request Changes]

### コードレビュー
- [ ] CLAUDE.md 準拠
- [ ] 横方向インポートなし
- [ ] セキュリティ問題なし

### テスト実行
- [ ] E2E: 全パス
- [ ] Unit: 全パス

### ブラウザ操作確認
- [ ] 主要シナリオの動作確認
- [ ] エッジケースの動作確認
- [ ] UX/UIに違和感なし

### 指摘事項
（あれば記載）
```

## 判定基準

| 判定 | 条件 |
|---|---|
| **Approve** | 全チェックOK、テスト全パス、ブラウザ操作問題なし |
| **Request Changes（コード修正）** | テスト失敗、バグ、規約違反 → 開発者に差し戻し |
| **Request Changes（要件の問題）** | テストシナリオ自体が不適切、要件漏れ → プランナーに差し戻し |
